## نطاق المرحلة الأولى

الطلب ضخم جدًا لتسليم واحد. أقترح تسليم **المرحلة الأولى القابلة للنشر** الآن، مع بنية بيانات جاهزة لكل الرياضات لاحقًا. أخبرني إن أردت تعديل النطاق قبل التنفيذ.

### ما سيُبنى الآن (يعمل فعليًا)

**البنية التحتية**
- Lovable Cloud (Postgres + Auth + RLS) — سأفعّله في أول خطوة
- عربي RTL افتراضي + تبديل EN/LTR، هوية أخضر سعودي/أبيض/فحمي عبر design tokens في `src/styles.css`
- shadcn/ui، حالات loading/empty/error، متجاوب 375px→1440px، WCAG AA

**الصفحات والمسارات**
- `/` الرئيسية: مباريات مباشرة/اليوم، مسابقات، آخر الأخبار، ملاعب قريبة
- `/matches` مركز المباريات: تبويبات الآن/اليوم/غدًا/الأسبوع/الشهر/السنة + فلاتر (مسابقة، منطقة، مدينة، فريق) + تقويم
- `/matches/$id` تفاصيل المباراة: نتيجة، ملعب، تشكيلات، أحداث زمنية، إحصاءات، تعليق حي (يعتمد على البيانات المخزّنة)
- `/competitions`, `/competitions/$id` (ترتيب + هدافون)
- `/teams/$id`, `/players/$id`
- `/explore` مستكشف: المملكة → منطقة → مدينة → حي (فرق، بطولات، مباريات، ملاعب)
- `/venues` قائمة + خريطة (Google Maps عبر Lovable) + فلاتر (قرب، سعر، أرضية، مرافق، تقييم، توفر)
- `/venues/$id` تفاصيل + تقويم أوقات + حجز
- `/bookings` حجوزاتي، `/favorites`, `/notifications`, `/search`
- `/auth` تسجيل/دخول (Email + Google)
- `/admin` لوحة إدارة (رياضات، مناطق، مدن، أحياء، مسابقات، فرق، مباريات، ملاعب، اعتمادات)
- `/owner` لوحة مالك ملعب (ملاعبه، حجوزاته، أوقاته)

**نموذج البيانات (كل الجداول المطلوبة)**
`sports, regions, cities, neighborhoods, competitions, seasons, teams, players, team_memberships, venues, venue_facilities, venue_slots, matches, match_events, standings, bookings, profiles, user_roles, favorites, notifications, articles, media_assets, audit_logs` — كلها UUID، فهارس مناسبة، RLS، عزل بيانات مالك الملعب.

**قواعد حرجة**
- منع double booking بـ `EXCLUDE USING gist` على `(venue_id, tstzrange(start_at, end_at))` + دالة حجز ذرية `SECURITY DEFINER`
- الأدوار في جدول `user_roles` منفصل + دالة `has_role()` (منعًا لتصعيد الصلاحيات و RLS recursion)
- Sports data adapter (`src/lib/sports-provider/`) بواجهة موحّدة، تنفيذ حالي = قراءة من DB؛ ربط API مرخّص لاحقًا يستبدل الـ adapter فقط
- Audit log لكل عمليات الإدارة
- شارة "بيانات تجريبية" ظاهرة عبر الموقع

**Seed data سعودية خيالية**
- 5 مناطق، ~12 مدينة، ~20 حي
- دوري خيالي "دوري الرياضة المحلية" بموسم حالي، 10 فرق خيالية، ~150 لاعب
- ~30 مباراة (مباشرة، مجدولة، منتهية) مع أحداث وإحصاءات
- ~15 ملعب عبر مناطق مختلفة مع مرافق وأوقات متاحة
- ~8 مقالات، ترتيب وهدافون محسوبان

### ما لن يُبنى الآن (يحتاج قرارًا/عقودًا)

- ❌ دفع حقيقي (الحجز تجريبي بتأكيد فقط، بدون بوابة)
- ❌ ربط مزود نتائج مباشر (Adapter جاهز، بلا مفاتيح)
- ❌ Scraping أو أي محتوى/شعارات Kooora/أندية حقيقية
- ❌ إشعارات Push حقيقية (نخزّن الإشعارات داخل التطبيق فقط)
- ❌ رياضات أخرى غير كرة القدم في UI (الجداول تدعمها؛ سنضيف UI عند الطلب)

### ملاحظات مهمة قبل التنفيذ

1. **الحجم**: هذا مشروع ضخم — سيتطلب ~40–60 ملف. سأنفّذه على دفعات في هذه الجلسة، ابدأ من الأساس (Cloud + schema + design system + auth + routes الأساسية) ثم أكمل الطبقات.
2. **الخريطة**: سأستخدم Google Maps Platform (Managed by Lovable) لصفحة الملاعب — سأطلب التفعيل عند الوصول لتلك الخطوة.
3. **PDPL**: صفحة سياسة خصوصية مبسّطة + عدم تسجيل بيانات حساسة في audit_logs.
